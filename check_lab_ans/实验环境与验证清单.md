# 换电脑后的实验环境与验证清单

整理日期：2026-10-22。这是后续实验的操作参考，不是本次测试结果。

## 先确认两个仓库的角色

本仓库 `FDU-CS30066-ComputerNet` 保存课程资料和中文笔记。实验实现要使用课程提供的 Minnow starter；不要在资料仓库根目录运行 Minnow 的 CMake 命令，也不要把参考作者仓库当成本校 starter。

另一台电脑已有本资料仓库时，可在其目录运行：

```bash
git pull --ff-only origin master
```

如果提示无法快进，先检查两台电脑各自的提交和工作区，再处理分支差异。不要用强制覆盖来“完成同步”。

## 构建和目标核对

在实际 Minnow 项目根目录运行：

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build -N
```

若所用生成器提供帮助目标，可以运行 `cmake --build build --target help` 查看目标。然后按实际任务运行 `check0`、`check1` 等；测量和集成章节未必各有一个同名自动测试，不能机械地假定 `check0` 到 `check7` 都存在。

命令依据：[CMake](https://cmake.org/cmake/help/latest/manual/cmake.1.html)、[CTest](https://cmake.org/cmake/help/latest/manual/ctest.1.html)。

## 验证覆盖范围

| 模块 | 必须观察的行为 |
| --- | --- |
| ByteStream | 容量限制、顺序、关闭后读尽、累计计数、吞吐率 |
| Reassembler | 乱序/重叠/重复、边界裁剪、结束标记、pending |
| Wrap32 / Receiver | 回绕、SYN/FIN、累计 ACK、窗口及错误状态 |
| Sender | 窗口、部分 ACK、重复 ACK、FIN、超时、零窗口 |
| NetworkInterface | 帧过滤、ARP 学习、请求节流、过期、缓存队列 |
| Router | 最长前缀、默认路由、TTL、校验和、下一跳 |
| 测量 | 原始数据、总发送数、缺失样本、统计方法与图 |
| 端到端 | 双向通信、关闭、文件完整性、不同实现互通 |

每完成一个模块，再验证受影响的前置模块。改变 ByteStream 会影响所有依赖它的测试；改变路由器通常不需要反复验证无关的 HTTP 拼接逻辑。

## 对照参考实现的顺序

1. 比较 `.hh` 公共接口，确认属于同一代 Minnow。
2. 对照状态含义和边界处理，而不是只比较函数体长短。
3. 查看是否修改了测试、框架或增加额外功能，避免把扩展行为误认为课程要求。
4. 在自己的课程测试上验证；本目录没有认证任何参考仓库的正确性或本校兼容性。

源代码与报告中引用外部资料时记录来源。每次实际实验保留命令、目录、错误输出、修改理由和真实测试结果，后续按本校要求生成报告。
