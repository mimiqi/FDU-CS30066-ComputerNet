# Checkpoint 6：IP Router 参考讲解

资料入口：[Winter 2024 讲义归档](https://github.com/yyym-y/Stanford-CS144/blob/f6116c31133bf2514db0ae924755520cf3fc236b/file/Lab%20Checkpoint%206-building%20an%20IP%20router.pdf)、[RFC 1812](https://www.rfc-editor.org/rfc/rfc1812.html)、[RFC 791](https://www.rfc-editor.org/rfc/rfc791.html)。2023 历史版对应 check5。

## 路由选择的答案

一条路由包含网络前缀、前缀长度、可选下一跳和输出接口。目的地址可能匹配多条路由，应选择前缀最长的一条。`/0` 是默认路由，`/32` 是精确主机路由。

课程规模下，先用顺序表保存条目、逐条比较即可；无需为了数据结构复杂度先实现一棵路由树。相同长度的等价路由如何处理，应采用 starter 或测试规定的确定规则。

## 转发步骤

1. 取出各输入接口队列中的待处理 IPv4 数据报。
2. 按目的 IP 寻找最长前缀匹配；没有匹配则丢弃。
3. TTL 为 0 或 1 时丢弃，避免对无符号 TTL 先减再判断而下溢。
4. 其余数据报 TTL 减一，更新 IPv4 头校验和。
5. 有显式下一跳时发给它；直连路由没有下一跳时，发给数据报最终目的 IP。
6. 将数据报交给选中的 NetworkInterface，MAC 解析由它负责。

本实验是简化转发器。不要把生产路由器规范中的全部 ICMP、路由协议和分片处理都假定为本次待实现任务。

## 手算路由表

以下是自行构造的示例，接口和网关只用于推演：

| 前缀 | 下一跳 | 接口 |
| --- | --- | --- |
| `0.0.0.0/0` | `198.51.100.1` | 0 |
| `10.0.0.0/8` | 直连 | 1 |
| `10.6.0.0/16` | 直连 | 2 |
| `10.6.2.0/24` | `192.0.2.9` | 3 |

- 目的 `10.6.2.5`：四条都匹配，选择 `/24`，接口 3，下一跳 `192.0.2.9`。
- 目的 `10.6.8.5`：选择 `/16`，接口 2，下一跳是 `10.6.8.5` 本身。
- 目的 `203.0.113.7`：选择默认路由，接口 0。
- 同样的匹配结果下，TTL=1 仍应丢弃；TTL=2 转发后变为 1。

## 两个容易遗漏的细节

前缀比较可以用掩码，也可以比较高位，但 `/0` 必须单独处理：C++ 对 32 位整数移位 32 位并不是合法的“自动得到零”。另一个细节是 TTL 位于 IP 头内，修改它会改变头校验和。原作者的 [路由器记录](https://pcloud.dev/cs144-checkpoint-6/) 也专门指出这两个问题。

路由器只改变此跳相关的转发信息，不把 IP 目的地址改成网关地址；链路层下一跳地址与网络层最终目的地址应始终分开。
