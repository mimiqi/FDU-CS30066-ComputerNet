## 核心问题及答案

输入是带起始位置的字符串片段，可能乱序、重复和重叠。输出只能是从位置 0 开始、没有空洞的连续数据。可先把问题建模为“已知字节所在区间的并集”，而不是“到达消息的队列”。讲义假设不同片段之间的内容一致。

设 `C` 为总容量、`P` 为输出流累计已消费量、`A` 为累计已组装写入量，则：

```text
输出流缓存范围：[P, A)
允许存放的未组装位置：[A, P + C)
第一个不可接受的位置 U = P + C = A + output.available_capacity()
```

这是从容量约束推导出的下标模型。未组装数据占据窗口中的位置，不能又用 pending 数量把右边界减一次，否则会错误缩小接收范围。

## 一种解题步骤

使用按起点排序、互不重叠的区间集合：

1. 收到片段 `[start, end)`，记录原始结束位置；若携带结束标记，它描述原始流终点，不能用裁剪后长度重算终点。
2. 将数据裁剪到 `[A, U)`；已经输出的数据和右侧超出容量的数据不再缓存。
3. 与已有区间求并集，去除重叠部分的重复存储；相邻区间也可以合并。
4. 若最左侧区间从 A 开始，就将连续前缀写入输出流并更新 A，重复直到遇到空洞。
5. 已知流终点且 A 到达该终点时，关闭输出流的写入端。

区间端点统一使用半开区间能减少边界错误。合并前后 pending 统计的是未输出的唯一字节数，不是收到的所有片段长度之和。终点与容量边界的精确处理需和本校测试对照。

## 手算答案

设容量 8，读端尚未消费：

| 输入 | 输出流逻辑内容 | 未组装内容 | pending |
| --- | --- | --- | ---: |
| `(3, "def", false)` | 空 | `[3,6) = def` | 3 |
| `(1, "bcde", false)` | 空 | `[1,6) = bcdef` | 5 |
| `(0, "ab", false)` | `abcdef` | 空 | 0 |
| `(6, "ghij", false)` | `abcdefgh` | 空 | 0 |

最后一条只接收位置 6、7；位置 8、9 超出当前窗口。应用消费数据后窗口才会继续向右移动。此前丢掉的字节不会自动恢复，需要调用者之后重新提供。

## 边界问答

- **结束标记先到，前面有空洞怎么办？** 记住终点，补齐到终点再关闭。
- **完全重复的片段怎么办？** 唯一字节集合不变，pending 不增长。
- **输出流里已有数据但应用没读，能否继续接收无限乱序片段？** 不能，输出缓存和未组装数据共同受容量约束。
- **能否看到缺口后继续写后面的字节？** 不能，否则破坏顺序。
