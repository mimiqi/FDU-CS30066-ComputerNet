# 构建、测试与调试资料

整理日期：2026-10-22。以下命令供另一台 Linux 实验机使用，本次资料整理没有执行这些命令。

## 统一命令的工作目录

下列构建与测试命令都从 **课程 Minnow 项目根目录**运行，即有 `CMakeLists.txt` 的目录。它不是存放本文的 `check0/examples/`。

[CMake 命令行文档](https://cmake.org/cmake/help/latest/manual/cmake.1.html) 可查 `-S`、`-B`、`--build`、`--target`：分别指定源码树、构建树、执行构建及选择目标。课程自定义目标名来自 [本地实验说明第 6—10 页](../check0.pdf)。

```bash
# 配置：源码在当前目录，构建产物放在 build
cmake -S . -B build

# 编译
cmake --build build

# webget 测试
cmake --build build --target check_webget

# Checkpoint 0 测试与性能检查
cmake --build build --target check0
```

如果当前已经位于 `minnow/build/`，其中的 `build` 相对路径含义会改变。建议返回项目根目录后统一使用上面的命令。

课程提交前还要格式化并重新验证；tidy 按本地提交章节列为可选检查：

```bash
cmake --build build --target format
cmake --build build --target check0
cmake --build build --target tidy
```

格式化可能修改文件，最终 Git 提交应包含这些变化。

## 查看某个失败测试

[CTest 官方文档](https://cmake.org/cmake/help/latest/manual/ctest.1.html) 可查 `-N`、`-R` 和 `--output-on-failure`。项目配置和构建完成后，可以参考：

```bash
# 只列出注册的测试名称
ctest --test-dir build -N

# 按名字筛选字节流测试，并打印失败输出
ctest --test-dir build -R byte_stream --output-on-failure
```

测试名称以本机列出的结果为准。`--test-dir` 从 CMake 3.20 起提供；若本机版本较旧，可进入构建目录运行：

```bash
cd build
ctest -N
ctest -R byte_stream --output-on-failure
```

CTest 直接运行已注册的测试，通常不会替你完成所有构建步骤。课程的 `check0` 目标可能还组织了额外检查；上面的筛选命令用于定位问题，最终仍执行课程要求的目标。

## GDB 阅读入口

[GDB 官方命令概览](https://sourceware.org/gdb/current/onlinedocs/gdb.html/gdb-man.html) 中最常用的是：

| 命令 | 用途 |
| --- | --- |
| `break 文件:行号` | 在指定源码位置设断点 |
| `run` | 启动被调试程序 |
| `next` / `step` | 逐行执行，分别跨过或进入函数调用 |
| `print 表达式` | 查看变量或表达式的值 |
| `bt` | 查看调用栈 |
| `continue` | 继续运行 |

下面是调用形式示例，其中路径要替换为本机实际生成的测试可执行文件：

```text
gdb ./build/tests/<测试程序名>
```

[课程官方 FAQ](https://cs144.github.io/lab_faq.html) 建议阅读测试源文件，定位失败的小场景；遇到疑似卡住的测试，可在 GDB 中中断执行并查看调用栈。直接运行单个测试能辅助诊断超时，但不能作为已经通过规定时间限制的证据。

## 如何阅读 AddressSanitizer 报告

[Clang AddressSanitizer 文档](https://clang.llvm.org/docs/AddressSanitizer.html) 说明它可以发现越界访问、释放后使用、返回后使用等内存错误。出现报告时，先保存完整输出，查看错误类型、访问位置和相关对象的分配或生命周期信息。

与 ByteStream 相关的一个检查点是 `string_view` 引用的数据是否仍然有效；具体原因必须根据实际报错确定。

本地 PDF 第 2 页还给出了针对 `AddressSanitizer:DEADLYSIGNAL` 的实验虚拟机设置办法。这里保留 [原文入口](../check0.pdf)，供实际出现该现象时核对环境；本次资料整理没有修改任何系统设置。
